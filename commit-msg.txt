一、封面横幅取景（修竖幅图裁掉人物头部）

横幅是固定 330px 高的容器加 object-fit: cover，实际只显示原图纵向一小段。
用逐行像素统计（亮度 / 饱和度 / 肤色占比）定位主体后发现之前的方向是反的：

  Docker 封面 803x1043  主体在纵向 41%-51%，顶部 0%-10% 是浅色背景（肤色 0%）
  JWT 封面   1600x1128  主体在纵向 21%-33%

所以给 Docker 篇设 coverPosition: top 等于把主体整个排除在外，只能拍到头发。
容器 1040x330 下，竖幅图缩放后 1040x1351，实际只显示 24.4% 的原图高度，
取景位置的可选区间很窄。实测换算记录在 docs/ASSET_SOURCES.md。

- JWT 篇 coverPosition 由 center 35% 改为 center 24%，主体完整且上方留白约占
  可视高度 17%
- Docker 篇放弃横幅：主体区间与 24.4% 的可视高度矛盾，取景没有舒服的解

二、Docker 篇改为入门向，并隐藏横幅

内容整体重写为面向刚接触容器的人：

- 开头用「发给同事跑不起来」的具体场景说明它解决什么问题
- 用表格讲清镜像与容器的关系（安装包 / 正在运行的程序）
- 七行 Dockerfile 起步，逐行解释为什么先 COPY 依赖清单再 COPY 代码
- 专门一节讲「容器起来就退出」：三种常见写错方式 + 固定排查动作
- RUN 与 CMD 的对照表，-p 端口映射的左右顺序
- 数据不能放容器里：两种挂载的区别与各自适用场景
- 「停止每次等 10 秒」的成因（PID 1 默认忽略未注册的信号）与 exec form
- 容器时区差 8 小时，以及更根本的做法
- 进阶一节：多阶段构建、非 root 运行、.dockerignore（含「镜像层永久」这条机制）
- 收尾是写 Dockerfile 的顺序清单，以及一组可以照着敲的练习命令

为配合内容调整了 slug：docker-process-filesystem-network -> docker-getting-started
（原标题是「进程、文件系统、网络」，与入门向内容已不符；旧地址是新上线页面，
无外部引用，直接 404 不保留重定向）

三、新增 hideCover 开关

列表页会把 cover 交给 next/image，所以不能简单删掉 cover 字段。
改为前端新增 hideCover 布尔项：保留封面用于列表缩略图，只隐藏文章页大横幅。
同时把 Post.cover 改为可选，并让两个列表页在无封面时走 no-cover 样式
（普通卡片配色，不再使用图上浅色文字与遮罩）。

封面图重新放回 Docker 篇正文作为插图，保留分层示意的作用。

四、featured 字段真正生效

两个列表页此前都直接取「最新一篇」当精选，frontmatter 里的 featured 字段
没有任何代码读取。同一天发布两篇时排序还不稳定，表现为精选位在两篇之间跳。
